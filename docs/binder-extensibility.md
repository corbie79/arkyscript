# 범용 C++ 바인더 확장

Arky의 바인더는 호스트가 사용하는 C++ 타입과 Lua VM에 연결합니다. 게임 엔진, 데스크톱 앱, 도구에서 같은 API를 사용할 수 있도록 타입 변환과 객체 수명 규칙을 공개 확장점으로 제공합니다. Cocos 통합은 이 구조를 검증하는 사용 사례입니다.

## 구성 원칙

| 구성 | 책임 |
| --- | --- |
| Arky 언어·타입 검사 | 스크립트의 타입·모듈·trait 계약을 검사 |
| C++ 바인더 | 함수 호출, 인자·결과 변환, 등록된 네이티브 타입 관계, Lua 참조·오류 처리 |
| 호스트 어댑터 | 외부 타입의 표현, 객체 유지·해제, 외부 객체 파괴 통지, 실행 스레드 연결 |
| 애플리케이션 등록 | 공개할 API 이름, 호출 형태, 반환 정책, 스크립트의 타입 선언 |

호스트 어댑터는 공개 API만 사용해야 합니다. 바인더 내부에 Cocos의 `Ref`, `_luaID`, `tolua` 이름을 넣지 않습니다. 기존 바인딩과의 호환 규칙은 어댑터에 둡니다. Arky 문법을 사용하지 않는 Lua 코드도 바인더를 사용할 수 있습니다.

현재 실행·바인딩 검증 대상은 LuaJIT입니다. 여러 애플리케이션에 연결할 수 있다는 의미의 범용성과 여러 Lua VM 버전의 호환성은 각각 검증합니다.

## 구현한 첫 확장점: 값 변환

`next2::luax::converter<T>`는 C++ 값 타입을 Lua 값으로 읽고 씁니다. 특수화에 `enabled = true`, `T read(lua_State*, int)`, `void push(lua_State*, ...)`를 제공합니다. `read`는 원래 스택을 유지하고 `push`는 한 값을 추가합니다. 호출 경계에서 스택 높이를 검사하고 C++ 예외로 중단된 변환의 임시 스택 항목을 제거합니다.

값 변환은 함수·프로퍼티·호스트 호출·객체 접근·컨테이너 내부에 동일하게 적용됩니다. 좌표를 `{x, y}`로, 시간 단위를 정수로, enum을 문자열로 표현할 수 있습니다. 변환된 값은 C++ 쪽에서 소유하며, const 참조 인자의 임시 값도 호출 동안 살아 있습니다.

이 API는 원래 C++ 객체를 가리키는 포인터의 수명을 결정하지 않습니다. 값 변환과 네이티브 클래스 등록을 같은 타입에 동시에 적용하지 않습니다. 규약과 실행 예제는 [바인더 안내](../binder/README.md#사용자-정의-타입-변환), [테스트](../tests/binder/converter.cpp)에 있습니다.

## 구현한 객체 수명 정책

`arky_ref_object<T>`와 `binder::reg_ref_object`로 native 객체의 소유권을 선택합니다. 클래스와 루트 정책을 등록한 뒤 자식 관계와 포인터를 노출합니다. 이 경로에서는 `shared_ptr`로 native 객체를 유지하지 않습니다.

| 모드 | 수명 결정권 | GC·VM 종료 |
| --- | --- | --- |
| `ref_ownership::native` | native 객체의 소유자 | 래퍼만 정리하며 native 참조 수를 변경하지 않음 |
| `ref_ownership::lua` | 호스트의 참조 계수와 Lua가 유지하는 참조 | 래퍼 생성 시 `addRef`, 정리 시 `decRef` |

VM별 weak 캐시는 같은 객체의 래퍼를 재사용합니다. 명시적으로 등록한 상속 관계를 따라 루트 주소를 계산하므로 부모 부분 객체의 주소 차이를 처리합니다. const와 mutable 접근 권한은 별도 래퍼로 유지합니다. 각 등록 계층의 정책은 고정하며 객체 노출 후 바꿀 수 없습니다.

native 소멸 시 호스트는 `invalidate_ref_object(root_pointer)`를 호출합니다. 남은 Lua 참조는 만료된 객체가 되고 같은 주소에 나중에 생성된 객체는 새 래퍼를 받습니다. pending GC 래퍼까지 무효화하여 이미 소멸한 객체를 다시 해제하지 않습니다. 이 통지는 VM 스레드에서 주소 재사용 전에 동기적으로 이루어져야 합니다. 외부 소멸 콜백은 VM 종료 전에 연결을 해제합니다.

보호된 소멸자를 가진 참조 계수 루트, 다중·가상 상속, 반복 GC, native 선소멸, GC 중 소멸, 주소 재사용, 여러 VM과 코루틴을 엔진 독립 테스트로 검증합니다. 규약과 예제는 [바인더 안내](../binder/README.md#native와-lua의-객체-소유권), [테스트](../tests/binder/ref_object.cpp)에 있습니다.

## 남은 객체 확장

- 세대 번호와 유효성 토큰을 사용하는 리소스 핸들, 다른 스레드에서 오는 소멸 통지의 동기화는 호스트 어댑터와 후속 API 설계가 필요합니다.
- 기존 tolua 등 외부 userdata를 읽고 쓰는 공개 연결점은 아직 제공하지 않습니다. 외부 표현을 해석하는 코드는 해당 어댑터가 담당합니다.
- 기본 생성자 기반 값 객체와 명시적 `shared_ptr` 바인딩은 계속 지원합니다. 참조 정책을 등록한 타입에는 이 소유권을 혼용하지 않습니다.

## 호출 규칙과 타입 선언

`cpp_class<T>::reg_method`는 명시적인 `T&`/`const T&` 첫 인자로 메서드를 감쌉니다. 기존 C++ 함수가 `void`를 반환해도 어댑터에서 self 포인터를 반환할 수 있습니다. `reg_raw_method`는 Lua C 함수를 직접 연결해 오버로드와 다중 반환을 구현하게 합니다. raw 함수의 인자 검사와 예외 경계는 호스트가 담당합니다.

`enable_instance_fields()`는 선택적으로 Lua 필드·콜백을 userdata에 보관합니다. 기본값은 등록한 native 멤버와 trait의 덮어쓰기를 막습니다. `instance_field_policy::allow_method_overrides`를 선택하면 인스턴스별 native 메서드에 Lua 함수를 대입하고 nil 또는 저장한 원래 함수로 복원할 수 있습니다. 프로퍼티와 trait은 계속 보호합니다. 가장 가까운 부모 설정을 상속하며 자식의 명시적 설정이 우선합니다. 환경 테이블은 VM의 강한 registry 참조를 만들지 않아 self를 캡처한 콜백도 수거됩니다. 타입 갱신·const 보호·메서드 감싸기·native 선소멸·VM 종료를 [호환 테스트](../tests/binder/compatibility.cpp)로 확인합니다.

다음 기능은 추가 설계가 필요합니다.

- 오버로드 선택과 기본 인자: 모호한 호출은 명확하게 거부하고, 엄격한 기본 타입 변환을 유지합니다.
- Lua 콜백: 함수 참조의 수명, 구독 해제, VM 종료, 실행 스레드를 함께 정의합니다.
- 바인딩 정보와 `.d.arky` 연결: 공개 이름·인자·결과·부모 관계의 불일치를 검사할 경로를 마련합니다. 런타임 바인딩만 제공해도 사용할 수 있어야 합니다.

네이티브 타입·trait 관련 설계는 [native-bindings.md](native-bindings.md)를 따릅니다.

## Cocos 적용 순서

먼저 엔진 의존성이 없는 바인더 테스트로 계약을 검증합니다. 이후 호스트 어댑터를 통해 `Ref`·`Node`·`Sprite`의 생성, 동일 객체 재노출, Lua 필드, 콜백, 파괴를 확인합니다. 기존 tolua 호출 규약과의 호환은 별도 테스트로 확인합니다.

Epic7와 SSR은 `yuna`를 공유하므로 Epic7에서 선택적으로 연결할 수 있어야 합니다. 바인더의 새 기능만으로 `luacocos2d` 전체 교체가 완료되었다고 판단하지 않습니다. 실제 적용 시 두 프로젝트의 호출부와 플랫폼 빌드도 확인합니다.
