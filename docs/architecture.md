# 독립 Rust 컴파일러와 공식 LuaJIT

구현 언어는 Rust다. Teal을 파서·타입 검사기·중간 언어로 사용하지 않는다. 사용자 코드는 Lua 문법과 GC 중심으로 유지하고, Rust의 소유권 규칙을 도입하지 않는다.

```text
                         Rust
.luax → lexer → AST → 타입 검사 → 타입 제거/Lua 생성 → 공식 LuaJIT
.lua → legacy 원본 로더 ───────────────────────────────────┘
```

## 현재 구성

| 구성 요소 | 역할 |
| --- | --- |
| `crates/tynex-compiler` | 외부 의존성 없는 Rust 라이브러리. AST·타입 검사·공개 타입·import 발견·선언 파일 파싱·Lua 생성 |
| `crates/tynex-cli` | CLI·설정·파일별 모드·프로젝트 탐색·모듈 의존 그래프·진단·실행 목록 생성·LuaJIT 프로세스 실행·stdio LSP |
| `runtime/runner.lua` | Rust 바이너리에 포함한 모듈 로더·실행·디버거 연결 코드. 컴파일러 기능은 없음 |
| `runtime/task/` | C++20 고정 OS worker 풀·Lua 네이티브 Task 모듈. 독립 VM과 값 복사 전송 |
| `scripts/` | Python 기반 공식 엔진 빌드·업데이트 도구. 사용자 스크립트 실행 경로와 분리 |
| `binder/` | C++20 함수·클래스 바인딩, 인자 변환, Lua 객체와 동적 값 |

Rust 코어는 파일 시스템과 프로세스 실행에 의존하지 않는다. 데스크톱 CLI와 LSP가 같은 모듈 검사·컴파일 API를 사용하며, 후속 앱 임베딩에서도 코어를 재사용할 수 있다. C ABI·Android/iOS 바인딩은 아직 없다. 현재 CLI는 외부 LuaJIT 프로세스를 실행하며 Rust 크레이트를 통해 다른 Lua VM을 함께 빌드하지 않는다.

## 검사와 실행

`.lua`의 기본 모드는 legacy다. 원본을 LuaJIT `loadfile`로 읽어 실행한다. legacy의 구문 검사·gen 검증은 본문을 실행하지 않고 `loadfile`만 호출하며 `LUA_INIT`을 제거한다. 문자열 인코딩을 Rust에서 강제로 재해석하지 않는다. Rust 래퍼의 실행 환경과 음수 `arg`까지 stock CLI와 완전히 같다고 보장하지는 않는다.

`.luax`의 기본 모드는 gradual이다. 타입 부족은 허용하지만 확인 가능한 불일치는 거절한다. strict는 추론할 수 있는 타입 표기를 요구하지 않고 미해결 변수·함수 인자·반환형을 진단한다. 명시적 any는 동적 경계다. 현재 기본 값·함수·테이블·조건문·반복문을 지원하며 미구현 문법은 파싱 오류다. 구체적인 범위는 [지원 문법](supported-language.md)을 따른다.

AST는 문장·표현식·함수·테이블 타입과 원본 span을 분리해 보관한다. 검사기는 어휘적 스코프마다 선언 계약과 현재 타입을 유지하고, 분기의 반환·계속 실행·break 경로를 합친다. 지역 변수의 nil 확인은 해당 경로에서 타입을 좁히고, 함수 호출·루프 경계에서는 보수적으로 초기화한다. 지연 실행되는 함수 본문은 외부 변수의 일시적인 좁히기를 상속하지 않는다.

함수 결과는 고정 위치 타입·최소 값 개수·가변 꼬리를 가진 값 목록으로 표현한다. 대입·호출 인자·return·테이블 마지막 원소에서만 마지막 호출/가변 인수를 확장하고, 괄호와 일반 표현식에서는 한 값으로 조정한다. 함수 반환 개수와 각 위치의 타입을 함께 합치므로 빈 반환과 명시적인 nil 반환을 구분한다. 다중 대입은 대상과 우변을 먼저 검사한 뒤 변수 흐름을 갱신한다.

메서드의 self 계약은 선언 시점의 수신 테이블에서 얻으며, 실제 호출 수신자가 기존 필드 계약을 유지하는지 검사한다. 새 함수 멤버는 정적 테이블 경로에 추가한다. 현재 별칭 전체로 멤버 확장을 전파하거나 조건부 확장을 증명하지는 않는다. 테이블 타입 스냅샷은 Rust 내부에서 공유하고 unknown 탐색은 방문한 테이블을 기억해, 메서드가 늘어날 때 타입 정보가 지수적으로 복제되지 않게 한다. 이는 사용자 Lua 테이블의 복제나 메모리 관리 규칙을 바꾸지 않는다.

테이블 타입은 고정 필드와 선택적인 인덱스 계약으로 구성한다. 배열·사전 조회는 원소가 없을 수 있으므로 optional이다. 새 테이블 리터럴은 기대 타입에 맞춰 검사하지만, 이미 존재하는 가변 테이블의 별칭을 더 넓은 필드 타입으로 변환하지 않는다. 표준 함수 시그니처와 pairs/ipairs 추론은 코어에 있는 초기 내장 목록이다. 레거시 모듈의 공개 계약은 `.d.luax`로 별도 선언할 수 있다.

그래프에서 발견한 타입 오류는 LuaJIT을 시작하기 전에 차단한다. check·gen은 typed 파일만 있으면 LuaJIT 없이 실행할 수 있다. legacy 의존 파일은 공식 엔진으로 구문만 검사한다. 타입 표기는 공백으로 지우고, import와 try는 파서가 기록한 토큰 범위에 따라 Lua로 변환한다. 현재 변환은 원본 줄바꿈을 유지하며 열 이동은 소스 맵으로 연결한다. shebang은 Lua 주석으로 바꾼다. try의 return/break는 종료 태그와 값 개수를 보관해 바깥 함수/반복문으로 전달한다.

진입 파일의 모드는 CLI > 파일 지시문 > 마지막 glob override > 설정 기본값 > 확장자 기본값 순서다. CLI 모드는 의존 모듈로 전파하지 않는다. 파일마다 가장 가까운 설정을 사용하되 `--project`는 전체 그래프의 설정 파일을 고정한다. 프로젝트 전체 check는 include/exclude로 시작 파일을 선택하고, 선택된 파일의 정적 의존은 exclude와 무관하게 검사한다.

## 모듈 그래프와 실행 목록

`prepare`는 AST와 원본, 타입 제거 및 문법 변환 범위를 보존한다. 정적 import는 require 바인딩과 무관하게 의존성을 발견하고 가져온 이름을 읽기 전용으로 검사한다. 검사기는 내장 require 바인딩의 호출을 발견하므로 지역 변수로 가린 require와 주석·문자열을 import로 오인하지 않는다. CLI는 문자열 리터럴 이름을 검색해 의존 모듈을 먼저 검사하고 `Interface`를 전달한다. 모듈이 require 별칭을 반환하는 경우에는 타입 전달 뒤 새로 드러난 import도 반복해서 찾는다. 공개 타입은 첫 반환 위치이며, 빈 반환/nil은 require의 기본 boolean 결과를 반영한다.

동일 호출 안에서는 경로별 검사 결과를 재사용하고 재귀 스택으로 정적 순환 참조를 진단한다. 디스크 증분 캐시는 아직 없다. 파일·깊이·반복 횟수를 제한해 무한 탐색을 방지한다. legacy 본문은 Rust로 파싱하지 않으므로 내부 의존 그래프도 추론하지 않는다. `.d.luax`의 `export: TYPE` 또는 named `declare`은 실행되지 않는 신뢰 계약이고 typed 구현에는 sidecar를 적용하지 않는다.

실행 목록에는 원본 경로·생성 Lua 경로·모듈 이름·검색 루트를 넣는다. 런처는 preload 다음, 일반 Lua 파일 로더 앞에 준비된 모듈 로더를 넣고 package.loaded 캐시를 사용한다. typed 청크에는 검사를 거친 require 래퍼를 제공해 로컬 모듈의 preload/기존 캐시 충돌 및 준비되지 않은 동적 로딩을 진단한다. 다른 전역 읽기/쓰기는 기존 전역 환경으로 전달한다. 원본 legacy 청크는 일반 환경을 유지한다. package 테이블 변경·외부 API는 동적 경계다.

정적 import는 실행 목록의 파일을 직접 로드하고 별도의 경로별 캐시를 사용한다. Lua의 require·preload·공개 캐시 변경이 import 대상을 바꾸지 않는다. 자세한 계약은 [import·예외 처리](imports-exceptions.md)에 있다.

`dynamic_modules`는 실행 전에 준비할 추가 루트다. 런타임 컴파일은 하지 않는다. `gen`은 의존을 검사하지만 진입 Lua만 출력한다. 다중 파일 배포와 임베딩은 후속 단계다. 자세한 검색·캐시·정책 범위는 [모듈 안내](modules.md)를 따른다.

## 원본 소스 디버깅

생성 코드는 `loadstring(code, '@' .. 원본절대경로)`로 로드하고 원본 행을 보존한다. 디버깅 시 JIT을 끄고 VS Code Local Lua Debugger 또는 Zed EmmyLua에 연결한다. 실행기·변환기와 디버거는 별도다. LSP는 실행 대신 같은 검사기의 진단을 전달한다.

Lua 디버그 훅을 사용한 자동 테스트는 원본 파일·행, 지역 변수, 호출 스택과 반복문의 테이블·인덱스·원소 값, 메서드 self와 여러 반환값을 받은 지역 변수를 검증한다. 타입을 붙이지 않은 공통 문법 예제는 공식 LuaJIT 직접 실행과 변환 후 실행 결과도 비교한다. 실제 VS Code 확장 호스트에서 `.luax` 예제의 원본 중단점·변수·식 평가·Step Over·정상 종료도 검증했다. Zed UI 검증은 확장자 변경 전 결과이며 [검증 기록](editor-validation.md)을 따른다. 번들은 일반 소스 맵과 조건부 중단점 위치 변환을 제공한다. async의 논리적 스택은 후속 작업이다. [디버깅 안내](debugging.md)

## 에디터 문서 스냅샷

`tynex lsp`는 열린 로컬 문서의 버전·텍스트를 보관한다. 각 갱신에서 동일한 buffer overlay를 모든 열린 진입 파일의 Project에 전달한다. resolve·선언 sidecar·파일 정책·최종 타입 검사는 CLI와 공유하고, 디스크에 없는 새 편집 파일도 부모 경로를 정규화해 검색한다. 오류가 있는 unit의 원본도 보존해 span을 UTF-16 진단 범위로 바꾼다.

닫힌 파일은 디스크로 되돌리고 의존하지 않는 파일의 기존 진단은 빈 목록으로 지운다. 동적 파일 감시를 지원하는 클라이언트에는 소스·설정 파일 감시를 등록한다. 설정은 저장된 TOML만 읽는다. 증분 파서·캐시·취소는 아직 없고, 순차적으로 전체 열린 그래프를 다시 검사한다. [에디터 안내](editors.md)

## 플랫폼 범위

배포 대상은 Android ARM64, iOS ARM64, Linux x64/ARM64, Windows x64다. Windows ARM64는 후속 대상이고 32비트는 지원하지 않는다. macOS ARM64에서 개발·로컬 검증한다. Rust 플랫폼 지원은 컴파일 대상의 존재를 의미하며 모든 엔진·네이티브 모듈·기기 동작을 검증했다는 뜻이 아니다. [Rust 플랫폼 문서](https://doc.rust-lang.org/rustc/platform-support.html)

모바일에서는 데스크톱 CLI를 외부 프로세스로 실행하는 대신 앱에 엔진을 넣는다. 배포 전에 Rust로 Lua를 생성하거나, 후속 Rust 코어 바인딩으로 앱에서 변환할 수 있게 한다. iOS는 일반 앱에서 JIT이 비활성화된 LuaJIT 인터프리터로 검증한다. [공식 iOS 안내](https://luajit.org/install.html#ios)

## 공식 엔진 업데이트

`dependencies.json`에는 공식 LuaJIT SHA만 남겼다. `.deps/luajit`은 공식 Git 객체 캐시다. 빌드마다 새 스냅샷으로 추출하며 생성 파일은 `build/native/<SHA>`와 `build/windows-x64/<SHA>`에 둔다. 체크아웃·다운로드 원본을 패치하지 않는다.

후보 업데이트는 네이티브·Windows 엔진 빌드와 Rust·Python 회귀 테스트를 수행한 뒤 SHA를 갱신한다. 실패나 동시에 발생한 버전 파일 편집이 있으면 기존 핀을 보존한다. Windows 실제 실행은 별도 CI 단계다. Rust 의존성은 `Cargo.lock`으로 고정한다. Python은 엔진 개발 도구에만 필요하다. [빌드·업데이트 안내](windows-build.md)

후속 작업은 [구현 계획](implementation-plan.md)에 정리했다.
